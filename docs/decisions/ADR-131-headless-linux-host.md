# ADR-131: Headless Linux host (`sirus-host`)

**Status:** Accepted (2026-10-13).

## Context

The phone app (ADR-080, ADR-081) reaches Sirus Code on the Mac over Tailscale. The Mac has to be awake and running the window, and agents run on the laptop. The owner wants the same thing on an always-on Linux server (an Ubuntu 24.04 aarch64 container on a VPS, as uid 1000, reachable only over Tailscale): the phone opens the same app, and Claude Code, Codex and OpenCode run there.

The back end was Tauri-shaped throughout: every module took `tauri::AppHandle` to emit events and reach `State<Arc<AppState>>`, ~170 `#[tauri::command]`s were the only entry points, and remote access ran each phone request through the main window's IPC (`Webview::on_message`), forwarded events with `listen_any` and served the UI through Tauri's asset resolver. Nothing could run without a window, and the crate did not build on Linux at all (`objc2-avf-audio` in the general dependencies, a few macOS-only items referenced from shared code).

## Decision

- **Two builds of one crate.** Cargo features: `desktop` (default: Tauri, its plugins, the window) and `host`. `cargo build --release --no-default-features --features host --bin sirus-host` builds a binary that does not link Tauri or WebKit. The desktop binary declares `required-features = ["desktop"]`; `sirus-host` declares `host`. macOS-only dependencies all sit in the `cfg(target_os = "macos")` section.
- **A runtime facade instead of rewriting every module.** `src-tauri/src/runtime.rs` exports `AppHandle`, `Emitter`, `Listener`, `Manager`, `State`, `EventId`, `async_runtime` and `http`. In the desktop build these are Tauri's own items; in the host build they are small stand-ins with the same shape: managed state (set once, lives for the process), an event bus with `emit`/`listen_any`/`unlisten` (payloads serialized once, as Tauri does), one global multi-threaded tokio runtime, `run_on_main_thread` on one dedicated thread (so code written for Tauri's main thread stays serialized) and `get_webview_window` that is always `None`. Shared modules import from `crate::runtime` and commands are `#[cfg_attr(feature = "desktop", tauri::command)]`; their bodies and signatures did not change. We considered an `EventSink` trait plus a hand-written `Host` type and rewriting the commands as thin wrappers over plain functions; it would have touched every command body and conflicted with ongoing work for no behavioural gain, since the facade *is* that trait boundary.
- **Commands: one list, generated table.** `build.rs` (host build only) reads the desktop's `generate_handler![…]` list in `lib.rs` and each command's signature, and writes the host's command table: `AppHandle` and `State<…>` parameters are injected, every other parameter is read from the request by its camelCase name (Tauri's rule; a missing key is `null`, so `Option` is `None`), `async` commands are awaited and plain ones run on the blocking pool (Tauri runs them off the async runtime too). A command added to the app reaches the host with no second list to maintain. The table leaves out the desktop-only modules (browser, browser recording, window reveal), the window's own commands in `lib.rs`, any command taking a window, and everything in remote access's `DENIED` list. Unknown commands answer `{ code: "remote" }`, as refused ones always did.
- **Remote access is the host's front door, unchanged in its rules.** `remote.rs` is shared: pairing codes, device tokens (SHA-256 at rest, max 10, revocable), the peer filter (loopback and Tailscale ranges), the `Origin` check, web push and `tailscale serve` HTTPS are the Mac app's. In the host build a request runs through the generated table instead of the window, events reach devices through the facade's bus, and the UI comes from `--ui-dir` (the built `dist/`; unknown paths answer the app shell, nothing outside the folder is read, symlinks out are refused). Every API route except the public bundle, `/api/health` and the code-guarded `/api/pair` still requires a device token whatever the peer address: the WebSocket's first message, `Authorization: Bearer` for push, `?token=` for thumbnails.
- **It listens on one address.** `serve --bind ADDR` (default: this machine's Tailscale IPv4, else `127.0.0.1` for `tailscale serve` in front; `0.0.0.0` only when asked). The Mac app keeps listening on every address and filtering peers. Pairing links use the bound address, the `tailscale serve` HTTPS name, or `--url`.
- **CLI.** `sirus-host serve [--data-dir DIR] [--bind ADDR] [--port 7710] [--ui-dir DIR] [--url URL]`; `sirus-host pair` prints the six-digit code, the links and a terminal QR; `sirus-host devices`; `sirus-host revoke <id>`. `pair`, `devices` and `revoke` talk to the running server over a private control socket (`host.sock`, `0600`, in the `0700` data folder) so a revocation closes the device's socket at once; with no server running, `devices` and `revoke` read and edit `remote.json` directly. The data folder defaults to `$SIRUS_DATA_DIR`, else `$XDG_DATA_HOME/sirus-code`, else `~/.local/share/sirus-code`, with the same layout as the Mac's (`state.db`, `remote.json`, `worktrees/`, …). `--mcp-browser` is the agents' Sirus tools child mode, as in the app.
- **Start-up and shut-down mirror the window's.** The host builds `AppState` with the same constructor (`AppState::new`), starts the agent tool bridge, secrets, crash resume, snooze, CI auto-fix and PR watch, and on SIGINT/SIGTERM runs the same clean-up as the app's exit (agents stopped, state persisted, escaped descendants killed).
- **The agent tool bridge is cross-platform.** `browser_mcp.rs`'s Unix-socket bridge used to be compiled out off macOS, which silently removed the `sirus_*` session tools, delegation, inline visuals, secret requests and PR watch. The bridge and those tools now run everywhere; only the browser tools stay with the Mac app and are not offered elsewhere.
- **Linux portability.** Terminals and project scripts use `$SHELL`, else `/bin/zsh` on macOS and `/bin/bash` elsewhere (`detect::default_shell`). The CLI search path adds `~/.npm-global/bin`, `$NPM_CONFIG_PREFIX/bin` and the newest nvm Node versions, where a server without a login shell keeps `claude`, `codex` and `node`. Tailscale's CLI is also looked up at `/usr/bin/tailscale`. `caffeinate` (keep the Mac awake) is never started off the Mac app. Window-bound code (appearance, notifications' native alerts, pickers, paste and drop, computer use, window snap, prompt-link delivery, dictation) is compiled out or answers "not available" in the host build: native macOS code is gated on `all(target_os = "macos", feature = "desktop")`, so the host behaves the same on a Mac and on Linux.
- **Capabilities.** `host_info` carries `capabilities { platform, headless, browser, computerUse, dictation, pickers }` so the UI can hide what the host cannot do. Phone alerts keep working: notifications reach paired devices through web push whether or not a window exists.
- **SQLite.** `state.db` sets `PRAGMA journal_size_limit` to 32 MiB, so a long-running host's WAL file shrinks back after big checkpoints.

## Consequences

- One back end: a fix to an agent, Git or persistence path lands in both the Mac app and the host. Dead code is judged by the desktop build (the host build allows it); the desktop build keeps `-D warnings`.
- New shared code must import Tauri items through `crate::runtime`, and Tauri-only APIs (dialogs, windows, plugins) need a `#[cfg(feature = "desktop")]` path. A new command in a desktop-only module must be added to `DESKTOP_ONLY` in `build.rs`; otherwise the host build fails, loudly.
- The host serves the phone app; there is no desktop window to drive it, the embedded browser and computer use are Mac-only, and file pickers do not exist (projects are added by path).
- `build.rs` reruns on any source change in host builds (cheap text parsing). Embedding the UI into the binary was left out: `--ui-dir` keeps the binary small and the UI updatable without rebuilding Rust.

## Addendum: the phone on a server (2026-10-13)

- **Host-aware words.** `host_info` also carries `hostName` (the machine's `gethostname`, without `.local`). The phone's `t` (`usePhoneTranslation`, `lib/phone-host.ts`) rewords every "Mac" as "server" / "servidor" when the host is not the macOS app (`hostKind`: headless or another platform), capitalized at the start of a text or sentence, before parameters are filled in. The Home offline pill and the Settings connection row show the host name (`hostLabel`); Diagnostics adds a Host row with the platform. Hosts older than this send no capabilities and count as the Mac.
- **Hidden features.** `hostFeatures` derives browser, computer use, dictation, pickers, devices and open-in-editor from the capabilities; on a server the phone hides the agent browser-access switch. The phone's microphone stays: it dictates with the browser's own speech recognition, not the host's.
- **Adding projects from the phone.** With no folder picker, the Projects page (header and empty state) and the Choose project sheet open Add project (`MobileAddProject`): clone `owner/repo` or a `https://github.com` address with an optional folder name, or type an existing folder's absolute path. Clones reuse `clone_project`, which gained an optional `folder` (one safe segment, `new_project::clone_folder`); they land in `~/Projetos` on the Mac and `~/projects` on a server (`cloneParent`), an existing folder is refused and the parent is created only inside the home folder. `add_project` now accepts only absolute (or `~`) existing directories without `..` (`new_project::typed_folder`). The phone pre-checks both (`lib/phone-projects.ts`) and shows progress and the host's error. Both commands are in the host command table through `lib.rs`'s handler list.
